  一. 概述

  1.1 课题背景(基于真实数据)
   - 随着企业实验室规模的扩大，消耗性资产管理变得日益复杂
   - 传统手工EXCEL记录方式效率低下，容易出错，难以进行有效追踪
   - 需要建立一个信息化系统来实现资产的全生命周期管理
   - 满足库存盘点、有效期预警、权限控制等管理需求

  1.2 编写目的
   - 分析消耗性资产管理系统的需求和功能
   - 设计完整的数据库模型和系统架构
   - 实现一个功能完善、操作简便的资产管理系统
   - 为实验室和机构提供高效的资产管理解决方案

  1.3 用户需求
   - 管理员：需要全面的系统管理权限，包括用户管理、权限分配
   - 操作员：需要进行资产入库、出库、转移等日常操作
   - 普通用户：需要查询资产信息、库存状态
   - 系统需要支持多角色权限控制、有效期预警、数据统计等功能

  二. 需求分析

  2.1 功能需求
   - 资产定义管理: 资产名称、分类、品牌、型号、单位、领用要求的管理
   - 分类管理: 资产分类的增删改查
   - 位置管理: 房间、柜子、货架的管理
   - 库存管理: 入库、出库、转移操作
   - 有效期预警: 过期或即将过期资产的预警
   - 权限管理: 基于角色的访问控制
   - 数据统计: 库存汇总、出入库记录统计
   - 数据导入: 支持Excel/CSV数据批量导入

  2.2 数据字典
   - 资产定义表: 资产ID(主键)、名称、分类ID(外键)、品牌、型号、单位、领用要求、是否有效、创建时间、更新时间
   - 分类表: 分类ID(主键)、分类名称(唯一)
   - 位置表: 位置ID(主键)、房间、柜子、货架、创建时间
   - 库存批次表: 批次ID(主键)、资产ID(外键)、位置ID(外键)、有效期、当前数量、备注、创建时间、更新时间
   - 入库日志表: 入库ID(主键)、批次ID(外键)、来源、数量、入库时间、操作员ID(外键)、备注、创建时间
   - 出库日志表: 出库ID(主键)、批次ID(外键)、去向、数量、出库时间、操作员ID(外键)、备注、创建时间
   - 用户表: 用户ID(主键)、用户名(唯一)、密码哈希、创建时间、更新时间、是否管理员
   - 角色表: 角色ID(主键)、角色描述
   - 用户角色表: 用户ID(外键)、角色ID(外键)、分配时间
   - 角色权限表: 角色ID(外键)、分类ID(外键)、授权时间

  2.3 数据流图
   - 顶层数据流图：系统与外部用户、数据源的交互
   - 一级数据流图：主要功能模块的数据流向
   - 二级数据流图：各功能模块内部的数据处理流程

  三. 可行性分析

  3.1 技术可行性
   - 采用成熟的技术栈：Node.js、Express、MySQL、React
   - 数据库设计采用规范化设计，支持事务处理
   - 前后端分离架构，便于维护和扩展
   - 使用JWT进行身份认证，保障系统安全

  3.2 应用可行性
   - 系统功能覆盖了资产全生命周期管理需求
   - 支持批量数据导入，提高工作效率
   - 具备权限控制机制，满足不同用户角色需求
   - 提供有效期预警功能，避免资产过期浪费

  4.1 实体

   - 出库日志实体: 出库操作记录
   - 用户实体: 系统用户信息
   - 角色实体: 系统角色信息

  4.2 实体属性局部E-R图
   - 资产定义实体: 资产ID、名称、分类ID、品牌、型号、单位、领用要求、是否有效、创建时间、更新时间
   - 分类实体: 分类ID、分类名称
   - 位置实体: 位置ID、房间、柜子、货架、创建时间
   - 库存批次实体: 批次ID、资产ID、位置ID、有效期、当前数量、备注、创建时间、更新时间
   - 入库日志实体: 入库ID、批次ID、来源、数量、入库时间、操作员ID、备注、创建时间
   - 出库日志实体: 出库ID、批次ID、去向、数量、出库时间、操作员ID、备注、创建时间
   - 用户实体: 用户ID、用户名、密码哈希、创建时间、更新时间、是否管理员
   - 角色实体: 角色ID、角色描述

  4.3 全局E-R图
   - 展示所有实体间的关系
   - 资产定义与分类的一对多关系
   - 库存批次与资产定义、位置的多对一关系
   - 入库/出库日志与库存批次、用户的多对一关系
   - 用户与角色的多对多关系

  五. 逻辑设计

  5.1 E-R图向关系模型的转变
   - dim_asset_definition: (asset_id, name, category_id, brand, model, unit, requirement, is_active, created_at,
     updated_at)
   - dim_category: (category_id, category_name)
   - dim_location: (location_id, room, cabinet, shelf, created_at)
   - fact_stock_batch: (batch_id, asset_id, location_id, expiry_date, current_quantity, remarks, created_at,
     updated_at)
   - fact_inbound_log: (inbound_id, batch_id, source, quantity, inbound_time, operator_id, remarks, created_at)
   - fact_outbound_log: (outbound_id, batch_id, destination, quantity, outbound_time, operator_id, remarks,
     created_at)
   - sys_user: (user_id, username, password_hash, created_at, updated_at, is_admin)
   - sys_role: (role_id, description)
   - user_roles: (user_id, role_id, assigned_at)
   - role_permission: (role_id, category_id, granted_at)

  5.2 数据模型的优化及规范化设计
   - 第一范式：确保每个字段都是原子值
   - 第二范式：消除部分函数依赖
   - 第三范式：消除传递函数依赖
   - 添加适当的索引以提高查询性能
   - 设计存储过程确保数据一致性

  六. 项目管理

  6.1 框架选择
   - 后端框架: Node.js + Express.js，轻量级且高效
   - 前端框架: React，组件化开发，状态管理
   - 数据库: MySQL，关系型数据库，支持事务处理
   - 认证机制: JWT，无状态认证

  6.2 开发平台
   - 开发环境: Windows 10/11, Node.js v16+, MySQL 5.7+
   - 开发工具: VS Code, MySQL Workbench
   - 版本控制: Git
   - 包管理: npm
